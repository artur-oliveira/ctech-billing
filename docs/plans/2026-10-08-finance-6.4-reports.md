# Finance 6.4 — Reports (F3 statement, F7 DRE and cash flow, F1 realised result) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a person read their money: **F3** an account's statement with a running balance, plus the three manual facts a statement needs (opening balance, transfer, reversal — and "undo a payment" for a settlement); **F7** the accrual DRE and the cash flow for a period, side by side with one line saying why they differ; **F1** gains the realised (cash) result of the month that 6.3b deliberately left out.

**Architecture:** The DRE already falls out of the cached `SUMMARY` rows (income/expense accounts are only touched by real P&L facts). Cash does not: an asset account's summary mixes real cash with transfers and opening balances, and a settlement's legs do not say which category the cash was for. So every leg gains a **flow** attribution chosen by the posting rule (the bill's category for a settlement, "not cash flow" for a transfer or an opening balance), carried onto the entry row with the transaction's kind, memo and a reference to its bill. Cash flow and statements are then **range Queries on the entry partitions**, folded by pure functions in `internal/domain/finance/report.go`; no new cache, no new table, nothing for `finance-rebuild` to reconcile.

**Tech Stack:** Go 1.27.2, Fiber v3, DynamoDB (api-commons Base); Next.js 16 static export, React 19, TanStack Query, `@aoctech/ui`, Tailwind 4, vitest + Testing Library.

**Spec:** [`docs/specs/2026-10-07-finance-erp-design.md`](../specs/2026-10-07-finance-erp-design.md) — § 3.1–3.3 (double entry, the two reports from the same entries, DRE groups), § 3.4 (a paid bill is corrected by reversing its settlement first), § 3.5 last bullet (F1 realised is cash, F7's DRE is accrual), § 4, § 7 (F1, F3, F7), § 9 phase 4. Builds on [6.2](2026-10-07-finance-6.2-persistence-and-spaces.md), [6.3](2026-10-07-finance-6.3-bills-and-recurrences.md), [6.3b](2026-10-08-finance-6.3b-console-screens.md).

## Scope decisions (read before executing)

1. **Flow lives on the leg; provenance lives in `PostMeta`.** Which category a cash movement counts under is accounting — the posting rule decides it, and `Reverse` must carry it over negated — so it is a field of `finance.Leg`. The memo (the bill's description, "Transferência") and the bill reference are provenance, like `Origin`, so they are `PostMeta` fields, written on the header and on each entry.
2. **Legacy entries need no backfill.** Before this phase the only facts touching a non-system asset account are settlements (there is no transfer or opening-balance route yet). An entry with no `flow` attribute is therefore cash and is reported under *Sem categoria*, never dropped. No migration, no `-backfill` flag.
3. **Cash means non-system asset accounts.** *A receber* (`Receivables`) is a system asset account; it moves at recognition, which is accrual. Cash flow, F1's realised result and the statement's account picker read only `class = asset && !system`.
4. **No new cache.** A statement and the cash flow query `ENTRY#{from}` … `ENTRY#~` once per account: the entries from `from` onward give both the period's rows and, subtracted from the cached balance, the opening balance. Cost grows with how far back the period starts, which for a person's or a small company's ledger is a few hundred rows a year. *ponytail: if a space ever has tens of thousands of entries per account, add a monthly closing-balance row in the same `TransactWriteItems`.*
5. **Opening balance is its own once-only route**, not a field of `POST /accounts`: an account `Put` and the opening transaction's `ADD balance` on the same item cannot share one `TransactWriteItems` (DynamoDB refuses two operations on one item). A conditional `OPENING#{account}` marker makes it once per account. The UI posts it right after creating an asset account, with its own intent, and offers a retry if only the second call failed.
6. **Reversal from the statement is for manual facts only** (`transfer`, `opening_balance`). A settlement entry offers **Desfazer pagamento**, which reverses the settlement *and* returns the bill to the open list in one transaction (`POST /bills/:id/unsettle`, verb `finance.settle` — the 6.2 rule "undoing a settlement is settling"). Recognitions and adjustments are only changed through their bill (edit/cancel), as in 6.3. The unsettled bill comes back with `auto_settle` off: if the job paid it and the person undid that, the job must not pay it again the next morning.
7. **Periods are months.** DRE and cash flow take `from`/`to` as `YYYY-MM` (at most 24 months); a statement takes civil dates (at most 366 days). The UI offers presets (Este mês, Mês passado, Últimos 3 meses, Este ano, Últimos 12 meses) and nothing finer in this phase.
8. **Cards are 6.5.** A card is a liability; nothing here reads liabilities. When 6.5 adds statement payments, their asset leg gets `flow = "card:{id}"` and the cash-flow report shows it as one line per card — no change to this phase's shapes.

## Global Constraints

- Go commands from `api/`, UI commands from `ui/`. Go 1.27.2 (`api/go.mod`).
- Money is `billing.Cents` (int64) in Go and integer centavos in TS; no floats anywhere, display through `money()`.
- Civil dates are `brcal.Date` / `YYYY-MM-DD` strings; months are `finance.Month` / `YYYY-MM`. Never `new Date("YYYY-MM-DD")` in the UI.
- Every finance route is a row of `financeRoutes()` (verb, scope, idempotency); every write carries an `Idempotency-Key` and goes through `SpaceIdempotency`.
- A route resolves the space first; a refused space reads nothing (6.2 invariant). Account ids from another space are `ErrUnknownAccount`/404 and write nothing.
- Every fact is one `TransactWriteItems` (header, entries, balance/summary `ADD`s, markers, bill change, audit).
- UI copy is pt-BR, plain, no em dash (`ui/DESIGN.md` "Copy and controls"), no internal names (`settlement`, `opening_balance`, `flow`, ids) on screen; styled `Select` from `@/components/ui/Select` only, its trigger showing the label.
- Every screen has loading, empty, error and role-hidden states; controls a role cannot use are hidden, the server stays the authority.
- `npm run lint`, `npm test`, `npm run build` (UI) and `make test`, `make vet`, `gofmt -l ./` (API) clean before each commit; integration tests with `make test-integration` where a task adds them. Commit messages carry no attribution trailer.

```go
// Leg is one side of a transaction on one account. Amount is signed: **positive
// is a debit, negative a credit.** ...(keep the existing comment)
//
// Flow says what a leg on a cash account (a non-system asset) counts as in the
// cash flow: a category id, FlowNone for movements that are not income or
// spending (a transfer between own accounts, an opening balance), or "" when
// unknown (entries posted before 6.4, reported as "Sem categoria"). The posting
// rule decides it; the reports only read it.
type Leg struct {
	AccountID string
	Amount    billing.Cents
	Flow      string
}

// FlowNone marks a cash leg that is not cash flow.
const FlowNone = "-"
```

In `Reverse`, keep the flow: `legs[i] = Leg{AccountID: l.AccountID, Amount: -l.Amount, Flow: l.Flow}`.

In `posting.go`:
- `SettleBill`: payable `legs = []Leg{{sys.Payables, b.Amount, ""}, {b.AccountID, -paid, b.CategoryID}}`; receivable `legs = []Leg{{b.AccountID, paid, b.CategoryID}, {sys.Receivables, -b.Amount, ""}}`; difference legs keep `Flow: ""` (they are on a category, not on cash).
- `Transfer`: `Leg{toAccountID, amount, FlowNone}, Leg{fromAccountID, -amount, FlowNone}`.
- `OpeningBalance`: `Leg{accountID, amount, FlowNone}, Leg{sys.OpeningBalance, -amount, ""}`.
- Any composite literal `Leg{x, y}` elsewhere in the package (and `finance.Leg{AccountID:…, Amount:…}` callers outside it) still compiles only if keyed; run `go vet ./...` and convert the unkeyed ones the compiler flags to keyed form.

// Entry is one leg as stored on an account, with what the statement shows.
type Entry struct {
	AccountID string
	TxID      string
	Leg       int
	Date      brcal.Date
	Amount    billing.Cents // signed, debit positive
	Kind      TxKind        // "" on entries posted before 6.4
	Flow      string
	Memo      string
	Ref       string // "bill:{id}" when a bill produced it
	Reversal  bool   // a reversal's entries carry the ORIGINAL kind, flow, memo and ref
	Reversed  bool   // set by the reader when a REVERSAL# marker exists
}

type StatementLine struct {
	Entry
	Balance billing.Cents // running balance after this line
}

type Statement struct {
	Opening, Closing billing.Cents
	Lines            []StatementLine
}

// BuildStatement: entriesFrom are the account's entries dated >= from, in key
// order; current is the cached balance. Lines are those with from <= date < to.
func BuildStatement(current billing.Cents, entriesFrom []Entry, from, to brcal.Date) Statement

type FlowLine struct {
	Flow   string        // category id, or "" for Sem categoria
	Amount billing.Cents // positive in, negative out
}

type CashMonth struct {
	Month    Month
	In, Out  billing.Cents // Out is a magnitude
	Openings billing.Cents // opening balances posted this month (FlowNone, KindOpeningBalance)
	ByFlow   []FlowLine    // sorted by Flow
}

type CashFlowReport struct {
	OpeningCash, ClosingCash billing.Cents
	Months                   []CashMonth // every month from..to, empty ones included
}

// CashFlow: balances are the current balances of the cash accounts; entriesFrom
// are all their entries dated >= first day of `from`.
func CashFlow(balances map[string]billing.Cents, entriesFrom []Entry, from, to Month) CashFlowReport

type DRECategory struct {
	AccountID string
	Amounts   []billing.Cents // one per month; positive raises the result
	Total     billing.Cents
}

type DREGroupLine struct {
	Group      DREGroup
	Categories []DRECategory
	Amounts    []billing.Cents
	Total      billing.Cents
}

type DREReport struct {
	Months []Month
	Groups []DREGroupLine   // in the fixed DRE order, groups with no rows omitted
	Result []billing.Cents  // per month
	Total  billing.Cents
}

// CategoryInfo is what DRE needs to know about an account.
type CategoryInfo struct {
	Class AccountClass
	Group DREGroup
}

func DRE(summaries map[SummaryKey]Totals, accounts map[string]CategoryInfo, from, to Month) DREReport

package finance

import (
	"slices"
	"strings"

	"gopkg.aoctech.app/billing/api/internal/domain/billing"
	"gopkg.aoctech.app/billing/api/internal/domain/brcal"
)

// Reports are folds over entries and summaries. They read only: what a report
// says is derived here, once, so the API and any later export agree.

// (types Entry, StatementLine, Statement, FlowLine, CashMonth, CashFlowReport,
// DRECategory, DREGroupLine, DREReport, CategoryInfo exactly as in Interfaces)

func BuildStatement(current billing.Cents, entriesFrom []Entry, from, to brcal.Date) Statement {
	var sinceFrom billing.Cents
	for _, e := range entriesFrom {
		sinceFrom += e.Amount
	}
	s := Statement{Opening: current - sinceFrom}
	bal := s.Opening
	for _, e := range entriesFrom {
		if e.Date.Before(from) || !e.Date.Before(to) {
			continue
		}
		bal += e.Amount
		s.Lines = append(s.Lines, StatementLine{Entry: e, Balance: bal})
	}
	s.Closing = bal
	return s
}

func CashFlow(balances map[string]billing.Cents, entriesFrom []Entry, from, to Month) CashFlowReport {
	var r CashFlowReport
	idx := map[Month]int{}
	for m := from; !to.Before(m); m = m.Next() {
		idx[m] = len(r.Months)
		r.Months = append(r.Months, CashMonth{Month: m})
	}
	var now, sinceFrom billing.Cents
	for _, b := range balances {
		now += b
	}
	byFlow := make([]map[string]billing.Cents, len(r.Months))
	for _, e := range entriesFrom {
		sinceFrom += e.Amount
		i, ok := idx[MonthOf(e.Date)]
		if !ok {
			continue // after `to`: only counts toward the opening
		}
		m := &r.Months[i]
		switch {
		case e.Kind == KindOpeningBalance:
			// an opening balance, or its reversal (same kind, opposite sign)
			m.Openings += e.Amount
		case e.Flow == FlowNone:
			// a transfer, or its reversal: cash moved between own accounts
		default:
			// A reversal undoes the side its original was on: a reversed payment
			// lowers Out instead of raising In, so gross figures do not swell.
			orig := e.Amount
			if e.Reversal {
				orig = -e.Amount
			}
			if orig > 0 {
				m.In += e.Amount
			} else {
				m.Out -= e.Amount
			}
			if byFlow[i] == nil {
				byFlow[i] = map[string]billing.Cents{}
			}
			byFlow[i][e.Flow] += e.Amount
		}
	}
	r.OpeningCash = now - sinceFrom
	r.ClosingCash = r.OpeningCash
	for i := range r.Months {
		m := &r.Months[i]

func DRE(summaries map[SummaryKey]Totals, accounts map[string]CategoryInfo, from, to Month) DREReport {
	var r DREReport
	idx := map[Month]int{}
	for m := from; !to.Before(m); m = m.Next() {
		idx[m] = len(r.Months)
		r.Months = append(r.Months, m)
	}
	n := len(r.Months)
	cats := map[string]*DRECategory{}
	for k, t := range summaries {
		info, ok := accounts[k.AccountID]
		i, inRange := idx[k.Month]
		if !ok || !inRange || (info.Class != ClassIncome && info.Class != ClassExpense) {
			continue
		}
		// Income raises the result by its net credits, expense lowers it by its net debits.
		v := t.Credits - t.Debits
		c := cats[k.AccountID]
		if c == nil {
			c = &DRECategory{AccountID: k.AccountID, Amounts: make([]billing.Cents, n)}
			cats[k.AccountID] = c
		}
		c.Amounts[i] += v
		c.Total += v
	}
	r.Result = make([]billing.Cents, n)
	for _, g := range dreOrder {
		line := DREGroupLine{Group: g, Amounts: make([]billing.Cents, n)}
		for id, c := range cats {
			if accounts[id].Group != g {
				continue
			}
			line.Categories = append(line.Categories, *c)
			for i, a := range c.Amounts {
				line.Amounts[i] += a
				r.Result[i] += a
			}
			line.Total += c.Total
		}
		if len(line.Categories) == 0 {
			continue
		}
		slices.SortFunc(line.Categories, func(a, b DRECategory) int { return strings.Compare(a.AccountID, b.AccountID) })
		r.Groups = append(r.Groups, line)
		r.Total += line.Total
	}
	return r
}

// Unsettle undoes a payment: the settlement is reversed and the bill goes back
// to the open list, in one transaction. auto_settle is turned off — if the job
// paid it and the person undid that, paying it again tomorrow would be wrong.
func (r *BillRepository) Unsettle(ctx context.Context, sp space.ResolvedSpace, billID string, date brcal.Date, meta PostMeta, now time.Time) (finance.Bill, error) {
	if err := sp.Require(space.Settle); err != nil {
		return finance.Bill{}, err
	}
	b, err := r.get(ctx, sp, billID)
	if err != nil {
		return finance.Bill{}, err
	}
	if b.Status != finance.BillPaid || len(b.TransactionIDs) == 0 {
		return finance.Bill{}, fmt.Errorf("%w: only a paid bill can be reopened", finance.ErrBillState)
	}
	settlement := b.TransactionIDs[len(b.TransactionIDs)-1]
	plan, err := r.ledger.planReverse(ctx, sp, settlement, date, billMeta(meta, *b), now)
	if err != nil {
		return finance.Bill{}, err
	}
	reopened := *b
	reopened.Status, reopened.PaidDate, reopened.AutoSettle = finance.BillForecast, brcal.Date{}, false
	openPK, openSK, _, _ := sparseKeys(sp, reopened)
	sk := BillSK(billID)
	values := map[string]types.AttributeValue{
		":forecast": str(string(finance.BillForecast)), ":paid": str(string(finance.BillPaid)),
		":n":  &types.AttributeValueMemberN{Value: strconv.Itoa(len(b.TransactionIDs))},
		":op": str(openPK), ":os": str(openSK), ":f": &types.AttributeValueMemberBOOL{Value: false},
		":now": r.stamp(now),
		":tx": &types.AttributeValueMemberL{Value: []types.AttributeValue{str(plan.TxID)}},
	}
	names := map[string]string{"#status": "status", "#n": "transaction_ids"}
	update := r.bills.BuildRawUpdateTxItem(sp.PK(), &sk,
		"SET #status = :forecast, auto_settle = :f, open_pk = :op, open_sk = :os, #n = list_append(#n, :tx), updated_at = :now REMOVE paid_date",
		"#status = :paid AND size(#n) = :n", names, values)
	items := append(append([]types.TransactWriteItem(nil), plan.Items...), update)
	if err := r.bills.TransactWrite(ctx, items); err != nil {
		if onlyConditionFailed(err) {
			return finance.Bill{}, finance.ErrBillState
		}
		return finance.Bill{}, err
	}
	reopened.TransactionIDs = append(append([]string(nil), b.TransactionIDs...), plan.TxID)
	return reopened, nil
}

func parseMonthRange(from, to string) (finance.Month, finance.Month, error) {
